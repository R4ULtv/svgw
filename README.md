# svgw

A browser-based SVG workspace for creating, editing, and exporting vector artwork. Use it without an account: drafts save locally in your browser. Self-host on Cloudflare to add online storage, version history, and public project links.

## Features

- Create a blank canvas, start from a sample, or open an SVG. Drop or paste artwork into an existing project as a new layer.
- Draw and edit with SVG-Edit tools, undo/redo, and a scrollable canvas with pan and zoom.
- Organize artwork with nested layers, visibility, locking, renaming, and drag-and-drop reordering.
- Edit fill, stroke, and opacity with HEX, RGB, HSL, and OKLCH color inputs.
- Resize the artboard, fit it to artwork, and use rulers, guides, and snapping.
- Autosave local drafts and download standard or SVGO-optimized SVGs. Optimization leaves the editable project intact.
- Switch between light and dark themes and customize keyboard shortcuts.
- On your own instance, save private online drafts, restore or pin versions, and publish selected snapshots.

SVG is the import/export format. Export Illustrator or Affinity artwork as SVG before importing; native `.ai` and `.afdesign` files are not supported. Local drafts belong to the current browser and site; download an SVG to keep a portable copy.

## Local development

Requires **Node.js 22.12+** and **pnpm**. The pnpm version is pinned in `package.json`.

```sh
git clone https://github.com/r4ultv/svgw.git
cd svgw
pnpm install
pnpm dev
```

Open [localhost:3000](http://localhost:3000). One Vite process serves the app and `/api/*` in the Workers runtime, with simulated local R2 storage. No Cloudflare account is needed for local development, and the checked-in configuration uses local storage rather than the production bucket.

To try online saving and publishing locally, generate an admin key before starting the dev server:

```sh
pnpm key
pnpm dev
```

`pnpm key` writes the key to `.svgw-admin-key` and configures `.dev.vars`. Both files are ignored by Git, and the command never prints the key. It keeps an existing key unless you pass `--rotate`.

Click **Login** in the editor header, or press **Cmd/Ctrl+Shift+K**, and enter the key. On macOS, copy it with `pbcopy < .svgw-admin-key`. The browser keeps it in `sessionStorage` for the tab; **Logout** removes it.

## Self-hosting on Cloudflare

One Cloudflare Worker serves the app and storage API. A private R2 bucket holds online projects and version snapshots; no separate database or scheduled job is required.

### Configure your instance

After installing dependencies, authenticate with Cloudflare and create an R2 bucket, or reuse one dedicated to this instance:

```sh
pnpm exec wrangler login
pnpm exec wrangler r2 bucket create my-svgw-projects
```

Update `wrangler.jsonc` before deploying:

- Set `name` to your Worker name.
- Set `r2_buckets[0].bucket_name` to your bucket name, keeping the binding named `PROJECTS`.
- Replace the bundled `svgw.raulcarini.dev` route with your own hostname. A [custom domain](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/) requires an active Cloudflare zone in your account. Alternatively, remove `routes` and set `workers_dev` to `true` to use a `workers.dev` address.

Keep the R2 bucket private. Enabling [public bucket access](https://developers.cloudflare.com/r2/buckets/public-buckets/) through `r2.dev` or an R2 custom domain would bypass the app's project visibility checks.

### Deploy

Generate the admin key and include it in the first deployment:

```sh
pnpm key
pnpm run deploy --secrets-file .dev.vars
```

`ADMIN_KEY` is a required Worker secret. The [`--secrets-file` option](https://developers.cloudflare.com/workers/configuration/secrets/#upload-secrets-alongside-code) uploads it alongside the code. The deployment script runs all checks and builds the app before deploying; Wrangler uses the configuration generated by the Cloudflare Vite plugin.

To validate the build and deployment bundle without publishing:

```sh
pnpm run deploy --dry-run --secrets-file .dev.vars
```

For later code updates, run `pnpm run deploy`; the existing Worker secret is preserved. View live logs with `pnpm exec wrangler tail`.

### Admin access

The app uses one admin key per instance, with access to every online project. There are no individual user accounts. Keep the key private and backed up; do not commit it or put it in client code or URLs.

To rotate it after deployment:

```sh
pnpm key --rotate
pnpm exec wrangler secret put ADMIN_KEY < .svgw-admin-key
```

Log in again with the replacement key. For an instance that has not been deployed yet, use the first-deployment command instead.

## Saving and publishing

- **Local drafts:** changes save after one second of inactivity. Visitors can open published projects and edit separate local copies without changing the online original.
- **Online drafts:** log in with your instance's admin key. New projects start as private online drafts; use **Save online** to upload an existing local project. Changed drafts autosave every 30 seconds while the editor is open. **Save online now** or **Cmd/Ctrl+S** saves immediately. Failed uploads keep the local draft and retry.
- **Publishing:** **Publish latest version** saves the current edits and makes that snapshot public at `/project/<id>`. Later autosaves remain private drafts until you publish again. **Make private** blocks future public reads; **Make public** exposes the previously published snapshot. Copies already downloaded by visitors remain on their devices.
- **Version history:** admins can restore or pin snapshots. The latest 100 versions are retained, along with pinned and published versions. Restoring creates a new draft version without changing the published snapshot.
- **Conflicts:** if another tab or device changes the online draft, autosave pauses. **Reload saved version** opens the current remote draft and preserves changed local edits as a separate backup.
- **Deletion:** deleting from **On this device** removes only the local copy. **Delete online project** removes the remote project and its history while retaining local copies.

Online project requests are limited to 8 MiB, and project names to 200 characters.

## Development commands

```sh
pnpm check          # Lint, formatting, and frontend/Worker TypeScript checks
pnpm lint           # Oxlint; warnings fail the check
pnpm lint --fix     # Apply safe lint fixes
pnpm format         # Format source, configs, and docs with Oxfmt
pnpm format --check # Check formatting without changing files
pnpm typecheck      # Frontend and Worker TypeScript checks
pnpm build          # Run all checks, then create the production build
pnpm types          # Regenerate Worker binding/runtime types after config changes
```

Build before running tests:

```sh
pnpm build
pnpm test
```

The test runner combines editor and color regression tests with storage API integration tests. It starts the compiled Worker with temporary R2 storage and a test-only key, without using production credentials or data. Filter by test name with `pnpm test --test-name-pattern='color'`.

## Project structure

Built with React, TypeScript, TanStack Start, Tailwind CSS, and shadcn/ui. SVG-Edit manages the document and edit history, IndexedDB stores local drafts, DOMPurify sanitizes SVG imports, and SVGO runs optimized exports in a browser Web Worker.

- `src/components/` — editor UI, landing pages, and shared components.
- `src/routes/` — the homepage and `/project/<id>` editor routes.
- `src/lib/` — the editor adapter, project persistence, cloud access, and export helpers.
- `src/server/worker.ts` — storage API and project access control.
- `src/server.ts` — combined Cloudflare/TanStack entry point.
- `src/workers/` — browser SVG optimization.
- `tests/` — editor, color, and storage API tests.

`src/routeTree.gen.ts` and `worker-configuration.d.ts` are generated files. TanStack Start uses SPA mode; production serves a static app shell with fallback routing for editor links.

See [editor performance notes](docs/performance.md) and [landing-page artwork sources](src/components/landing/brand-assets.md) for additional details.
